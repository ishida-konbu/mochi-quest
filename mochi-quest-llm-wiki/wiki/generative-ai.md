# 生成AI：創作餅の命名・商品説明・NPCの感想

ユーザーが採用した3用途のみを生成AIで拡張する。ゲームのルール・状態・人物の知識は決定論的なエンジンが管理し、AI文章はその表現層に限定する。

## 採用範囲

**AI-01 [REQ]** 以下の三用途を実装する。従来提案の自由会話、手紙、瓦版、クエスト生成、プロット生成、NPC行動決定は採用しない。NPCの自律行動には [NPC](npc-simulation.md) の通常のゲームAIを用いる。

| 機能 | 実行契機 | 出力 | 保存 |
|---|---|---|---|
| 創作餅の命名 | プレイヤーが「名前を提案」を選ぶ | 3候補程度、ユーザーが選択/編集 | 採用した名前をレシピに保存 |
| 商品説明 | 制作後の「説明を作る」/登録 | 事実に基づく短い説明1件 | 採用した説明をレシピに保存 |
| NPCの感想 | 実際に食べた、購入した、贈答したイベント後 | NPCらしい短い感想1件 | イベントIDに紐付けた確定文 |

食べたことと購入したことは異なる。購入のみなら味を断定せず、食べた事実がある場合のみ実食の感想を生成。生成AIの推論は一回の操作/イベントにつき原則一回、連打防止・キャッシュ。拒否、タイムアウト、設定OFF、API枠不足でも制作・販売・贈答を成立させる。

## 正本と入出力

**AI-02 [DESIGN]** 正本はゲーム側のレシピ・属性・NPC・イベント・関係度・事実。AIに出す入力は必要な最小構造データのみ。レシピの組み合わせ・効果・値段・評判・報酬・時間・物語進捗はAIが変更できない。プロバイダの出力は文字列候補のみ。AIに書き込みツールや任意コード実行権限を与えない。

```json
{
  "task":"product-description",
  "locale":"ja-JP",
  "requestId":"req_001",
  "promptVersion":1,
  "recipe":{
    "baseLabel":"白もち米",
    "ingredientLabels":["栗","柚子"],
    "finishLabel":"焼く",
    "seasoningLabel":"蜜",
    "shapeLabel":"丸餅",
    "techniqueLabels":["半搗き"],
    "attributes":{"sweetness":65,"aroma":82,"chewiness":62,"preservation":55},
    "allowedFacts":["栗を使用","柚子を使用","焼き餅","半搗き"]
  }
}
```

感想には追加で `npc:{name, occupation, voiceStyle, tastes, allowedKnownFacts}` と `event:{eventId, occasion, actuallyTasted, fitCategory, reactionTags}` を渡す。NPCの知識に含まれない地域や秘境由来の材料は、その由来・所在地を削除し、「香りのある果実」等の許容表現に変換。秘境の未公開レシピやメインシナリオの全文、ユーザーの個人情報・セーブ全体・自由入力の任意テキストは送信しない。プレイヤーのレシピ名を渡す必要がある場合は非命令データとして長さ・制御文字を制限する。

### 出力の厳密な契約

```json
{"names":["栗柚子もち","柚香栗餅","秋の香り餅"]}
```
```json
{"description":"栗のほくほくとした食感に柚子の香りを重ね、蜜でほんのり甘く仕上げた焼き餅。"}
```
```json
{"reaction":"柚子がふわっと香るね。こりゃ、お茶と一緒にいただきたい餅だ。"}
```

上記はテスト用例、AIの実測出力ではない。追加プロパティを禁止。初期文字数：候補名1〜20文字×最大3、説明20〜100文字、感想10〜100文字（Unicodeコードポイント基準、調整値）。配列の重複、空文字、HTML、URL、制御文字、明白な禁止表現を除外。日本語自然さ、世界観に合う言い回し、根拠との一致、NPCの口調を重視する。プレイヤー入力/出力はDOMの `textContent` 等で表示しHTMLとして解釈しない。説明に根拠のない健康効果、未使用食材、価格/評価、公式伝統餅の称号、実在地由来、秘密情報を含めない。

**AI-03 [DESIGN]** ローカル評価・許可タグに基づき、出力に含まれる明示的な食材・技法・地域・状態・効能の矛盾をチェックする。JSON Schemaに合格しても事実性は保証されない。怪しい出力は採用せず、正本から生成したテンプレートにフォールバック。命名/説明は採用前にユーザーが確認・編集できる。NPCの感想は安全な短い限定表現と自動チェックを使い、自由文に正史としての効力を一切持たせない。完全な意味検証が難しい場合はAIに許可された表現候補の選択・言い換えに限定する。

## プロバイダ戦略

| 方式 | 強み | 制約 | 方針 |
|---|---|---|---|
| ローカルのテンプレート/文法生成 | 常に動作、無料、モバイル対応、決定論的 | 表現の幅は有限 | 必須の代替処理・初期実装 |
| Cloudflare Workers AI | 既存のホスティング環境に統合しやすい、軽量端末でも生成可能 | 無料枠、レート制限、外部通信、モデル変更、濫用対策 | 無料対象モデル・アカウント設定を確認して第一候補として比較評価。明示承認後に有効化 |
| WebLLM / ブラウザの小型公開モデル | サーバー推論料金なし、ローカル | WebGPU・大きなモデル取得、メモリ・3D描画性能、モデル日本語品質 | 任意の実験モード。初期ロードに含めない |
| 開発時オフライン生成 | API料金を避けやすい、文例を事前評価 | 未知のレシピ組合せの即時生成にはならない | テンプレートや評価データ作成に利用可 |

**AI-04 [DESIGN]** `TextProvider.generate(task, payload, options)` の非同期インターフェース。テンプレート、実験的ローカル、Workers AIを交換可能にする。必須の起動コードにモデルやSDKの大容量ダウンロードを追加しない。推論結果を待たずにゲームの制作/売買は完了。生成中の表示、キャンセル、時間制限（初期案5〜8秒）、リトライは手動または高々1回。失敗で即時に代替文。端末にネット接続がなくても遊べる。キャッシュキーは `task + provider/model/promptVersion + recipe contentHash + approved fact set + (npc/event context if reaction)`。採用した文章はキャッシュの削除後もセーブ内で保持。既に採用済みの文を自動で上書きしない。

## Cloudflare採用時の実装条件

**AI-05 [DESIGN]** [技術出典](../raw/2026-11-25-technical-references.md)では、2026-11-18時点のWorkers AI無料割当は10,000 Neurons/日。モデル別料金や使用可否は変わる。導入時に公式ページと実アカウントで再確認し、超過課金を発生させない構成を採る。無料枠がなくてもAI以外の全機能は利用可能。利用数を無料枠の最大人数と混同しない。プロバイダ/APIモデルの本番選定は [O-05](decisions.md) とする。

- 既存 `worker.js` は音楽配信とASSETSを担当。新APIを採用する場合は `POST /api/mochi-text` 等の専用ルートを先に分岐し、Wranglerの `run_worker_first` 対象とAI bindingを明示的に構成する。音楽Range、静的ファイル、ゲームパスの挙動を保持。ブラウザにAPIキーを置かない。
- サーバーでタスク・スキーマ・入力サイズ（初期案4KB以下）、最大出力トークン、生成回数・タイムアウト、同一オリジン/リクエスト検証を強制。Originだけで濫用対策が成立すると思わない。セッション/ネットワーク単位の上限に加え、並行数と日次の共有予算をサーバー側で制限。必要な状態管理サービスと費用が無料制約を満たすか確認。安全な共有制限を構成できない場合は公開APIを無効のままにする。
- 個人情報・任意プロンプト・ユーザー自由入力全文は受け取らない。出力/ログに機密を残さない。明示的なAI有効化/無効化と外部通信の説明。悪用時に速やかに停止できるサーバー側kill switch。LLM向け指示とユーザーデータは分離。
- 無料枠が尽きた/制限が返った/外部障害/不正出力の場合は正常なフォールバック（HTTP失敗をゲームのエラーにしない）。本番課金設定変更、秘密情報、公開API有効化は明示指示を待つ。

## 品質評価とリリース条件

**AI-06 [DESIGN]** 代表的な20〜30件以上のレシピ（甘い/塩味、包み/焼き/乾燥、変わった組合せ、秘密由来、無調味）×3用途からテスト。NPCの複数個性・購入のみ/試食あり・好みに合う/合わないを網羅する。自然な日本語、簡潔さ、事実一致、秘密漏洩なし、不適切な効能なし、NPCの口調、JSON成功率、実機での待ち時間とGPU負荷を比較。スキーマ違反や矛盾はすべて安全に代替処理へ。生成モデルの有用性がテンプレートを上回るか人間が確認。品質や無料運用が成立しなければ、3用途のUIとアダプタは完成させつつ標準はテンプレート、実際のモデル有効化は未完了と報告する（AI導入完了と偽らない）。

標準プレイにモデルダウンロード・外部推論は不要。適切な無料のモデル/プロバイダが確認できた段階で、3用途だけを選択式で有効化し、リリース前に [受け入れテスト](acceptance-tests.md) を満たす。
